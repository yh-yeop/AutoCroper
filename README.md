# AutoCroper · 흰 여백 자르기

**바로 쓰기: https://yh-yeop.github.io/AutoCroper/**

스캔본 · 흰 배경 사진의 흰 여백을 자동으로 잘라 내는 정적 웹앱. 빌드 도구 없이 `index.html` + `style.css` + `app.js`만으로 동작하고, **모든 처리는 브라우저 Canvas 안에서만** 한다(이미지는 서버로 전송되지 않음).

## 사용법

1. 이미지를 끌어다 놓거나, 영역을 눌러 고르거나, <kbd>Ctrl</kbd>+<kbd>V</kbd>로 붙여 넣는다. 여러 장 동시에 가능.
2. 카드마다 왼쪽이 원본(크롭 영역은 빨간 점선, 바깥은 어둡게), 오른쪽이 결과.
3. **저장 폴더**를 지정하면 ZIP 없이 결과가 그 폴더에 바로 저장된다. **처리되면 바로 폴더에 저장**을 켜면 이미지를 넣기만 해도 폴더에 결과가 생긴다. 지정하지 않으면 카드의 **다운로드** · **전체 ZIP 다운로드**로 받는다.
4. 파일명은 `원본이름_crop.jpg|png`, 한 파일에서 여러 장으로 나눈 경우 `원본이름_crop_1.jpg`, `_2` …

### 여러 장 자동 분리

스캐너에 사진 여러 장을 한꺼번에 올려 스캔한 파일은 사진별로 나눠 카드가 따로 생긴다(읽는 순서: 위 → 아래, 왼쪽 → 오른쪽). 나뉜 사진마다 기울기 보정 · 흰 틈 제거가 따로 적용된다. 잘못 나뉘었으면 카드의 **분리 취소**로 원래대로 되돌린다. 사진이 하나뿐이거나 문서면 나누지 않는다.

### 고급 설정 (평소엔 접혀 있음)

옵션을 바꾸면 모든 이미지에 바로 다시 계산되고, 이 기기에 기억된다. 접힌 제목 옆에 기본값과 다르게 바꾼 옵션 수가 보인다.

| 옵션 | 기본 | 설명 |
|---|---|---|
| 여러 장 자동 분리 | 켬 | 위 설명 참고. |
| 흰색 임계값 | 40 (5~120) | 흰색(255,255,255)과의 최대 채널 차이가 이 값을 넘으면 내용. 연한 내용이 잘리면 낮춘다. |
| 노이즈 필터 | 5 (0~10) | 행/열 하나에 내용 픽셀이 그 줄 길이의 n‰(0.1%) 미만이면 먼지로 보고 무시. 0이면 끔. |
| 자동 기울기 보정 | 켬 | 비스듬히 스캔된 사진의 테두리 각도를 재서 똑바로 돌린다(±15°, 0.1° 미만은 그대로). 카드에 보정 각도가 표시된다. |
| 사진 가장자리 흰 틈 제거 | 켬 | 살짝 기운 사진의 모서리 흰 쐐기, 사진과 종이가 섞인 옅은 경계선까지 안쪽으로 다듬는다. |
| 추가 여백 | 0px | 결과 둘레에 흰 여백을 더한다(이미지 밖으로 나가면 흰색으로 채움). |
| 회전 | 0° | 0/90/180/270°, 크롭 전에 적용. 전체 일괄 + 카드별 ⟲ ⟳. |
| 출력 포맷 | JPEG 92 | JPEG(품질 50~100) 또는 PNG. |

## Windows에 설치

### 설치 파일(.exe) — 권장

1. [Releases](https://github.com/yh-yeop/AutoCroper/releases/latest)에서 `AutoCroper-Setup-버전.exe`를 받아 실행한다.
2. 설치 마법사에서 **설치 폴더를 직접 고를 수 있다**. 바탕화면 · 시작 메뉴 바로가기가 생긴다.
3. 앱에서 **폴더 선택**으로 저장 폴더를 정하면 다음 실행 때도 기억한다. 탐색기에서 이미지를 오른쪽 클릭 → **연결 프로그램 → AutoCroper**로 바로 열 수도 있다.
4. 인터넷 없이 동작하고, 이미지는 기기 밖으로 나가지 않는다.

코드 서명이 없는 설치 파일이라 처음 실행할 때 Windows SmartScreen이 "PC 보호" 창을 띄울 수 있다. **추가 정보 → 실행**을 누르면 된다.
지우기: Windows 설정 → 앱 → AutoCroper → 제거.

### 설치형 웹앱(설치 파일 없이)

Edge · Chrome으로 https://yh-yeop.github.io/AutoCroper/ 를 열고 화면 위 **앱으로 설치**(또는 주소창의 설치 아이콘 · 메뉴 → 앱 → 이 사이트를 앱으로 설치). 시작 메뉴 · 작업 표시줄에 독립 창 앱으로 들어가고 인터넷 없이도 동작한다. 저장 폴더 기능도 Edge · Chrome에서 그대로 쓸 수 있다. Microsoft Store용 패키지(MSIX)가 필요하면 [PWABuilder](https://www.pwabuilder.com/)로 만들 수 있다.

## 알고리즘

1. 이미지를 Canvas에 그려 픽셀을 읽는다. 투명 영역은 흰색으로 합성.
   - **병렬 처리**: CPU 코어 수만큼(코어−1, 2~8개) Web Worker 풀을 띄운다. 큰 이미지는 가로 띠로 나눠 여러 워커가 동시에 분석한 뒤 합치고(결과는 통째로 분석한 것과 비트 단위로 같음), 여러 장은 풀에서 동시에 처리된다. 다운로드 · ZIP의 최종 그리기와 JPEG/PNG 인코딩도 워커에서 동시에 한다(결과에 필요한 부분만 잘라 넘김). 미리보기 축소도 메인 스레드를 막지 않도록 비동기로 한다.
   - 4코어에서 2000×2800 8장(분석 + JPEG 인코딩): 순차 약 1.0초 → 동시 약 0.5초.
   - OffscreenCanvas · Worker를 쓸 수 없는 브라우저는 메인 스레드에서 띠 단위로 쉬어 가며 처리한다.
2. 픽셀마다 `d = 255 − min(R,G,B)`(흰색과의 최대 채널 차이)를 구하고, 행별 · 열별로 "d > t 인 픽셀 수"를 모든 t에 대해 한 번에 세어 둔다. 그래서 임계값 · 노이즈 필터를 움직여도 픽셀을 다시 읽지 않고 즉시 다시 계산된다(4000×6000에서 분석 약 0.25초, 재계산 수 ms).
3. 내용 픽셀 수가 노이즈 기준 이상인 첫/마지막 행 · 열로 경계 상자를 잡는다. 하나도 없으면 원본을 유지하고 경고를 띄운다.
4. **자동 기울기 보정**: 경계 상자 네 변의 가운데 70% 구간에서 줄마다 처음 만나는 내용 픽셀 위치를 모아 직선을 맞춘다(Theil–Sen, 튀는 점에 강함). 점의 80% 이상이 직선에서 2px 안에 있는 '곧은 변'끼리 각도가 0.3° 안으로 맞으면 그 각도만큼 반대로 돌린 보정본을 만들어(워커에서, 바깥은 흰색) 다시 분석한다. 테두리가 들쭉날쭉한 문서 · 그림, 한 변만 비스듬한 사진은 보정하지 않는다. 각도별 보정본은 캐시해 임계값을 움직여도 각도가 같으면 다시 만들지 않는다. 합성 테스트에서 0.3°~10° 오차 0.02° 이내, 보정 후 원래 사진 크기를 그대로 되찾는다.
5. **가장자리 다듬기**: 경계 상자만으로는 ① 사진이 살짝 기울어 생기는 모서리의 흰 쐐기 ② 사진·종이가 섞인 1~2px 옅은 경계선이 남는다. 상자 바깥 여백에서 종이 밝기를 재고, 네 변 중 흰 틈이 가장 심한 변을 한 줄씩 안쪽으로 옮긴다(종이색 1% 초과, 줄 끝이 종이색, 양 끝 밝은 픽셀 1% 이상, 3줄 안쪽보다 60% 미만으로 옅음 중 하나). 상자 가운데에 종이색이 5% 넘게 보이면 문서처럼 성긴 내용이므로 건너뛴다. 한 변에서 최대 6%까지만 깎는다(기울기는 앞 단계에서 보정되므로 여기선 남은 1~3px 틈만 다룬다).
6. 기울기 보정 → 90° 단위 회전 → 크롭 → 추가 여백 순서로 원본 해상도 결과를 만든다.

## 테스트

[`test.html`](test.html)이 흰 배경 테스트 이미지를 Canvas로 만들어 실제 `app.js` 함수로 결과를 검증한다(경계 상자 정확도, 먼지 · 미색 노이즈, 임계값, 빈 이미지, 회전 방향, 여백, JPEG 압축, 기운 사진 · 옅은 경계선, 자동 기울기 각도 정확도 · 보정 후 크기 · 반듯한 사진/문서 미보정, 문서 미적용, 4000×6000 성능, 띠 분할 병렬 분석 = 단일 분석, 워커 렌더 = 메인 렌더 픽셀 일치, 여러 장 동시 처리 속도, 워커/메인 스레드 일치). 아래 "내 이미지로 확인"에서 직접 고른 이미지의 결과 네 변에 남은 종이색 비율도 볼 수 있다.

## 로컬에서 실행

Web Worker · 다운로드가 `file://`에서는 막히는 브라우저가 있으니 간단한 서버로 연다.

```bash
# 저장소 루트에서
python -m http.server 8000
# → http://localhost:8000/  ·  테스트: http://localhost:8000/test.html
```

## GitHub Pages 배포

1. 이 저장소를 GitHub에 push한다.
2. **Settings → Pages → Build and deployment**에서 Source를 **Deploy from a branch**, Branch를 **main**, 폴더를 **/ (root)** 로 두고 Save.
3. 잠시 뒤 `https://<사용자명>.github.io/<저장소명>/` 에서 열린다(이 저장소는 https://yh-yeop.github.io/AutoCroper/).

`.nojekyll`이 Jekyll 처리를 끄므로 파일이 그대로 배포된다. 외부 CDN 없이 JSZip 3.10.1을 [`vendor/jszip.min.js`](vendor/jszip.min.js)로 포함한다(MIT, [라이선스](vendor/JSZIP-LICENSE.md)).

## 파일

```
index.html             화면
style.css              모바일 우선 · 다크/라이트 자동
app.js                 크롭 코어(window.WhiteCrop) + UI. 워커 풀은 Blob URL로 생성
manifest.webmanifest   설치형 앱 정보(이름 · 아이콘 · 탐색기 연결 프로그램)
sw.js                  서비스 워커: 앱 파일 캐시로 오프라인 동작(이미지는 다루지 않음)
icons/                 앱 아이콘(일반 · 마스크용 · 파비콘)
test.html              알고리즘 테스트 페이지
vendor/jszip.min.js    ZIP 생성(로컬 포함)
.nojekyll              Pages에서 Jekyll 끄기
LICENSE                MIT
```

앱 파일을 고친 뒤에는 `sw.js`의 `VERSION`을 올려야 설치된 앱의 캐시가 확실히 바뀐다.

## 한계

- iOS Safari 등은 캔버스 최대 면적이 작아(약 1,670만 픽셀) 아주 큰 결과는 만들지 못할 수 있다. 그때는 카드에 안내가 뜬다.
- HEIC 등 브라우저가 열지 못하는 형식은 지원하지 않는다.
- 자동 기울기 보정은 ±15°까지, 테두리가 곧은 사진에만 적용된다. 보정하면 한 번 보간되므로 아주 미세하게 부드러워진다. 그보다 큰 회전은 90° 회전 버튼으로.
