# 흰 여백 자르기

스캔본 · 흰 배경 사진의 흰 여백을 자동으로 잘라 내는 정적 웹앱. 빌드 도구 없이 `index.html` + `style.css` + `app.js`만으로 동작하고, **모든 처리는 브라우저 Canvas 안에서만** 한다(이미지는 서버로 전송되지 않음).

## 사용법

1. 이미지를 끌어다 놓거나, 영역을 눌러 고르거나, <kbd>Ctrl</kbd>+<kbd>V</kbd>로 붙여 넣는다. 여러 장 동시에 가능.
2. 카드마다 왼쪽이 원본(크롭 영역은 빨간 점선, 바깥은 어둡게), 오른쪽이 결과.
3. 옵션을 바꾸면 모든 이미지에 바로 다시 계산된다.
4. 카드의 **다운로드**로 한 장씩, 위의 **전체 ZIP 다운로드**로 한꺼번에 받는다. 파일명은 `원본이름_crop.jpg|png`.

| 옵션 | 기본 | 설명 |
|---|---|---|
| 흰색 임계값 | 40 (5~120) | 흰색(255,255,255)과의 최대 채널 차이가 이 값을 넘으면 내용. 연한 내용이 잘리면 낮춘다. |
| 노이즈 필터 | 5 (0~10) | 행/열 하나에 내용 픽셀이 그 줄 길이의 n‰(0.1%) 미만이면 먼지로 보고 무시. 0이면 끔. |
| 사진 가장자리 흰 틈 제거 | 켬 | 살짝 기운 사진의 모서리 흰 쐐기, 사진과 종이가 섞인 옅은 경계선까지 안쪽으로 다듬는다. |
| 추가 여백 | 0px | 결과 둘레에 흰 여백을 더한다(이미지 밖으로 나가면 흰색으로 채움). |
| 회전 | 0° | 0/90/180/270°, 크롭 전에 적용. 전체 일괄 + 카드별 ⟲ ⟳. |
| 출력 포맷 | JPEG 92 | JPEG(품질 50~100) 또는 PNG. |

## 알고리즘

1. 이미지를 Canvas에 그려 픽셀을 읽는다(큰 이미지도 멈추지 않도록 Web Worker + OffscreenCanvas에서 가로 띠 단위로 처리, 지원하지 않으면 메인 스레드에서 쉬어 가며 처리). 투명 영역은 흰색으로 합성.
2. 픽셀마다 `d = 255 − min(R,G,B)`(흰색과의 최대 채널 차이)를 구하고, 행별 · 열별로 "d > t 인 픽셀 수"를 모든 t에 대해 한 번에 세어 둔다. 그래서 임계값 · 노이즈 필터를 움직여도 픽셀을 다시 읽지 않고 즉시 다시 계산된다(4000×6000에서 분석 약 0.3초, 재계산 수 ms).
3. 내용 픽셀 수가 노이즈 기준 이상인 첫/마지막 행 · 열로 경계 상자를 잡는다. 하나도 없으면 원본을 유지하고 경고를 띄운다.
4. **가장자리 다듬기**: 경계 상자만으로는 ① 사진이 살짝 기울어 생기는 모서리의 흰 쐐기 ② 사진·종이가 섞인 1~2px 옅은 경계선이 남는다. 상자 바깥 여백에서 종이 밝기를 재고, 네 변 중 흰 틈이 가장 심한 변을 한 줄씩 안쪽으로 옮긴다(종이색 1% 초과, 줄 끝이 종이색, 양 끝 밝은 픽셀 1% 이상, 3줄 안쪽보다 60% 미만으로 옅음 중 하나). 상자 가운데에 종이색이 5% 넘게 보이면 문서처럼 성긴 내용이므로 건너뛴다. 한 변에서 최대 6%까지만 깎으므로 약 2°보다 많이 기운 사진은 흰 쐐기가 남을 수 있다.
5. 회전 → 크롭 → 추가 여백 순서로 원본 해상도 결과를 만든다.

## 테스트

[`test.html`](test.html)이 흰 배경 테스트 이미지를 Canvas로 만들어 실제 `app.js` 함수로 결과를 검증한다(경계 상자 정확도, 먼지 · 미색 노이즈, 임계값, 빈 이미지, 회전 방향, 여백, JPEG 압축, 기운 사진 · 옅은 경계선, 문서 미적용, 4000×6000 성능, 워커/메인 스레드 일치). 아래 "내 이미지로 확인"에서 직접 고른 이미지의 결과 네 변에 남은 종이색 비율도 볼 수 있다.

## 로컬에서 실행

Web Worker · 다운로드가 `file://`에서는 막히는 브라우저가 있으니 간단한 서버로 연다.

```bash
# 저장소 루트에서
python -m http.server 8000
# → http://localhost:8000/crop/  ·  테스트: http://localhost:8000/crop/test.html
```

## GitHub Pages 배포

1. 이 저장소를 GitHub에 push한다.
2. **Settings → Pages → Build and deployment**에서 Source를 **Deploy from a branch**, Branch를 **main**, 폴더를 **/ (root)** 로 두고 Save.
3. 잠시 뒤 `https://<사용자명>.github.io/<저장소명>/crop/` 에서 열린다.

저장소 루트의 `.nojekyll`이 Jekyll 처리를 끄므로 파일이 그대로 배포된다. 외부 CDN 없이 JSZip 3.10.1을 [`vendor/jszip.min.js`](vendor/jszip.min.js)로 포함한다(MIT, [라이선스](vendor/JSZIP-LICENSE.md)).

## 파일

```
.nojekyll              (저장소 루트) Pages에서 Jekyll 끄기
crop/
  index.html           화면
  style.css            모바일 우선 · 다크/라이트 자동
  app.js               크롭 코어(window.WhiteCrop) + UI. 워커는 Blob URL로 생성
  test.html            알고리즘 테스트 페이지
  vendor/jszip.min.js  ZIP 생성(로컬 포함)
```

## 한계

- iOS Safari 등은 캔버스 최대 면적이 작아(약 1,670만 픽셀) 아주 큰 결과는 만들지 못할 수 있다. 그때는 카드에 안내가 뜬다.
- HEIC 등 브라우저가 열지 못하는 형식은 지원하지 않는다.
- 크게 기운 사진은 기울기 보정이 필요하다(지금은 90° 단위 회전만).
