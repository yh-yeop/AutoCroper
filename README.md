# AutoCroper · 흰 여백 자르기

스캔본 · 흰 배경 사진의 흰 여백을 자동으로 잘라 내는 도구. 기울기 보정, 한 번에 여러 장 스캔한 파일 분리, 저장 폴더에 바로 저장까지 한다. **모든 처리는 이 기기 안에서만** 이뤄지고 이미지는 서버로 전송되지 않는다.

- **웹에서 바로 쓰기:** https://yh-yeop.github.io/AutoCroper/ (설치형 웹앱으로도 설치 가능)
- **Windows 설치 파일:** [Releases](https://github.com/yh-yeop/AutoCroper/releases/latest) — 설치 폴더 선택 · 자동 업데이트
- **소개:** https://yh-yeop.github.io/p/autocroper/

![AutoCroper 화면](docs/screenshot.webp)

빌드 도구 없이 `index.html` + `style.css` + `app.js`로 동작하는 정적 웹앱이고, 같은 파일을 Electron으로 감싸 Windows 설치 파일을 만든다.

## 사용법

1. 이미지를 끌어다 놓거나, 영역을 눌러 고르거나, <kbd>Ctrl</kbd>+<kbd>V</kbd>로 붙여 넣는다. 여러 장 동시에 가능.
2. 카드마다 왼쪽이 원본(크롭 영역은 빨간 점선, 바깥은 어둡게), 오른쪽이 결과.
3. **저장 폴더**를 지정하면 ZIP 없이 결과가 그 폴더에 바로 저장된다. **처리되면 바로 폴더에 저장**을 켜면 이미지를 넣기만 해도 폴더에 결과가 생긴다. 지정하지 않으면 카드의 **다운로드** · **전체 ZIP 다운로드**로 받는다.
4. 파일명은 `원본이름_crop.jpg|png`, 한 파일에서 여러 장으로 나눈 경우 `원본이름_crop_1.jpg`, `_2` …

### 여러 장 자동 분리

스캐너에 사진 여러 장을 한꺼번에 올려 스캔한 파일은 사진별로 나눠 카드가 따로 생긴다(읽는 순서: 위 → 아래, 왼쪽 → 오른쪽). 나뉜 사진마다 기울기 보정 · 흰 틈 제거가 따로 적용된다. 잘못 나뉘었으면 카드의 **분리 취소**로 원래대로 되돌린다. 사진이 하나뿐이거나 문서면 나누지 않는다.

**다시 나누기:** 덜 나뉘었거나 안 나뉘었으면 카드의 **여러 장이면 나누기**(나뉜 카드는 **다시 나누기**)를 누른다. 문서 판정을 느슨하게, 조각 합치기 끄기, 흐린 · 밝은 사진, 작은 사진 순으로 더 민감한 설정을 차례로 시도해 지금보다 많은 사진이 나오는 첫 결과를 쓴다. 잘못 나뉘었으면 **한 장으로 되돌리기**.

### 고급 설정 (평소엔 접혀 있음)

옵션을 바꾸면 모든 이미지에 바로 다시 계산되고, 이 기기에 기억된다. 접힌 제목 옆에 기본값과 다르게 바꾼 옵션 수가 보인다.

| 옵션 | 기본 | 설명 |
|---|---|---|
| 여러 장 자동 분리 | 켬 | 위 설명 참고. |
| 흰색 임계값 | 40 (5~120) | 흰색(255,255,255)과의 최대 채널 차이가 이 값을 넘으면 내용. 연한 내용이 잘리면 낮춘다. |
| 노이즈 필터 | 5 (0~10) | 행/열 하나에 내용 픽셀이 그 줄 길이의 n‰(0.1%) 미만이면 먼지로 보고 무시. 0이면 끔. |
| 자동 기울기 보정 | 켬 | 비스듬히 스캔된 사진의 테두리 각도를 재서 똑바로 돌린다(±45°, 0.1° 미만은 그대로). 카드에 보정 각도가 표시된다. |
| 사진 가장자리 흰 틈 제거 | 켬 | 살짝 기운 사진의 모서리 흰 쐐기, 사진과 종이가 섞인 옅은 경계선까지 안쪽으로 다듬는다. |
| 추가 여백 | 0px | 결과 둘레에 흰 여백을 더한다(이미지 밖으로 나가면 흰색으로 채움). |
| 회전 | 0° | 0/90/180/270°, 크롭 전에 적용. 전체 일괄 + 카드별 ⟲ ⟳. |
| 출력 포맷 | JPEG 92 | JPEG(품질 50~100) 또는 PNG. |

## Windows에 설치

### 설치 파일(.exe) — 권장

1. [Releases](https://github.com/yh-yeop/AutoCroper/releases/latest)에서 `AutoCroper-Setup-버전.exe`를 받아 실행한다.
2. 설치 마법사에서 **설치 폴더를 직접 고를 수 있다**. 바탕화면 · 시작 메뉴 바로가기가 생긴다.
3. 앱에서 **폴더 선택**으로 저장 폴더를 정하면 다음 실행 때도 기억한다. 탐색기에서 이미지를 오른쪽 클릭 → **연결 프로그램 → AutoCroper**로 바로 열 수도 있다.
4. 인터넷 없이 동작하고, 이미지는 기기 밖으로 나가지 않는다.

**자동 업데이트:** 앱이 켜질 때와 6시간마다 새 버전을 확인해 뒤에서 받아 두고, 준비되면 화면 위에 "다시 시작해 업데이트"가 뜬다. 그냥 닫아도 다음 실행 때 설치된다. 화면 아래 **업데이트 확인** · 메뉴(Alt) → 도움말 → 업데이트 확인으로 직접 확인할 수도 있다.

코드 서명이 없는 설치 파일이라 처음 실행할 때 Windows SmartScreen이 "PC 보호" 창을 띄울 수 있다. **추가 정보 → 실행**을 누르면 된다.
지우기: Windows 설정 → 앱 → AutoCroper → 제거.

### 스캐너로 바로 스캔 (설치 파일 전용)

설치 파일 버전에는 화면 위에 **스캔** 줄이 있다. 스캐너를 고르고(평판 / 급지기, 150~600dpi, 컬러 / 흑백) **스캔**을 누르면, 스캔한 이미지가 바로 분리 · 기울기 보정 · 크롭을 거쳐 저장 폴더에 저장된다(처리되면 바로 저장을 켠 경우). 급지기는 넣은 장수만큼 연속으로 받는다. Windows 스캐너 표준(WIA)을 쓰므로 PC에 스캐너 드라이버(예: 삼성 · HP 스캔 드라이버)가 설치돼 있어야 한다. 웹 브라우저는 스캐너에 접근할 수 없어 웹 버전에는 없다.

**감시 폴더:** 쓰던 스캐너 프로그램(스캐너 버튼으로 PC에 저장 등)을 그대로 쓰고 싶으면, 그 프로그램이 저장하는 폴더를 **감시 폴더**로 지정한다. 새 스캔 파일이 생길 때마다 자동으로 가져와 처리한다(JPEG · PNG · BMP 등, TIFF는 미지원).

### 설치형 웹앱(설치 파일 없이)

Edge · Chrome으로 https://yh-yeop.github.io/AutoCroper/ 를 열고 화면 위 **앱으로 설치**(또는 주소창의 설치 아이콘 · 메뉴 → 앱 → 이 사이트를 앱으로 설치). 시작 메뉴 · 작업 표시줄에 독립 창 앱으로 들어가고 인터넷 없이도 동작한다. 새 버전이 배포되면 스스로 감지해, 작업 중인 이미지가 없으면 바로 새 버전으로 바뀌고 있으면 "지금 새로 고침" 안내가 뜬다. 저장 폴더 기능도 Edge · Chrome에서 그대로 쓸 수 있다. Microsoft Store용 패키지(MSIX)가 필요하면 [PWABuilder](https://www.pwabuilder.com/)로 만들 수 있다.

## 알고리즘

1. 이미지를 Canvas에 그려 픽셀을 읽는다. 투명 영역은 흰색으로 합성.
   - **병렬 처리**: CPU 코어 수만큼(코어−1, 2~8개) Web Worker 풀을 띄운다. 큰 이미지는 가로 띠로 나눠 여러 워커가 동시에 분석한 뒤 합치고(결과는 통째로 분석한 것과 비트 단위로 같음), 여러 장은 풀에서 동시에 처리된다. 다운로드 · ZIP의 최종 그리기와 JPEG/PNG 인코딩도 워커에서 동시에 한다(결과에 필요한 부분만 잘라 넘김). 미리보기 축소도 메인 스레드를 막지 않도록 비동기로 한다.
   - 4코어에서 2000×2800 8장(분석 + JPEG 인코딩): 순차 약 1.0초 → 동시 약 0.5초.
   - OffscreenCanvas · Worker를 쓸 수 없는 브라우저는 메인 스레드에서 띠 단위로 쉬어 가며 처리한다.
2. 픽셀마다 `d = 255 − min(R,G,B)`(흰색과의 최대 채널 차이)를 구하고, 행별 · 열별로 "d > t 인 픽셀 수"를 모든 t에 대해 한 번에 세어 둔다. 그래서 임계값 · 노이즈 필터를 움직여도 픽셀을 다시 읽지 않고 즉시 다시 계산된다(4000×6000에서 분석 약 0.25초, 재계산 수 ms).
3. 내용 픽셀 수가 노이즈 기준 이상인 첫/마지막 행 · 열로 경계 상자를 잡는다. 하나도 없으면 원본을 유지하고 경고를 띄운다.
4. **자동 기울기 보정**: 경계 상자 네 변의 가운데 70% 구간에서 줄마다 처음 만나는 내용 픽셀 위치를 모아 직선을 맞춘다(Theil–Sen, 튀는 점에 강함). 점의 80% 이상이 직선에서 2px 안에 있는 '곧은 변'끼리 각도가 0.3° 안으로 맞으면 그 각도만큼 반대로 돌린 보정본을 만들어(워커에서, 바깥은 흰색) 다시 분석한다. 테두리가 들쭉날쭉한 문서 · 그림, 한 변만 비스듬한 사진은 보정하지 않는다. 각도별 보정본은 캐시해 임계값을 움직여도 각도가 같으면 다시 만들지 않는다. 합성 테스트에서 0.3°~10° 오차 0.02° 이내, 보정 후 원래 사진 크기를 그대로 되찾는다.
5. **하얗게 날아간 하늘 되살리기**: 하늘처럼 종이와 거의 같은 밝기(d≈1~4)는 픽셀 하나로는 구별이 안 되지만 줄 평균으로는 다르다(종이 0.1~0.3). 내용 상자 바깥으로 한 줄씩 보며 평균이 종이보다 뚜렷이 진하고, 끝에 사진을 자른 경계선이 있을 때만 그 선까지 넓힌다(그림자 · 스캐너 가장자리는 넓히지 않음).
6. **가장자리 다듬기**: 경계 상자만으로는 ① 사진이 살짝 기울어 생기는 모서리의 흰 쐐기 ② 사진·종이가 섞인 1~2px 옅은 경계선이 남는다. 상자 바깥 여백에서 종이 밝기를 재고, 네 변 중 흰 틈이 가장 심한 변을 한 줄씩 안쪽으로 옮긴다(종이색 1% 초과, 줄 끝이 종이색, 양 끝 밝은 픽셀 1% 이상, 3줄 안쪽보다 60% 미만으로 옅음 중 하나). 상자 가운데에 종이색이 5% 넘게 보이면 문서처럼 성긴 내용이므로 건너뛴다. 한 변에서 최대 6%까지만 깎는다(기울기는 앞 단계에서 보정되므로 여기선 남은 1~3px 틈만 다룬다).
7. 기울기 보정 → 90° 단위 회전 → 크롭 → 추가 여백 순서로 원본 해상도 결과를 만든다.

**여러 장 분리**(원본 분석 직후, 기울기 보정 전에): 페이지를 최소 틈(짧은 변의 1%, 8px 이상)의 1/5 크기 격자로 줄여 '종이보다 확실히 진한' 칸을 고르고(종이 밝기에 맞춰 문턱을 정해 흐린 하늘 · 흰 옷도 사진으로 잡힘), 3×3 닫기로 사진 속 가는 흰 선을 메운 뒤 연결 성분으로 나눈다. 꽉 찬 칸 비율 0.7 이상 · 넓이 1.5% 이상(또는 반듯한 작은 사각형)만 사진 후보로 보고, 후보가 2개 이상이며 후보 밖 진한 픽셀이 10% 이하일 때만 나눈다(문서 · 그림 · 문서에 사진이 섞인 페이지는 그대로). 각 사진은 여백을 두고 잘라 이웃 사진 부분을 흰색으로 지운 뒤, 사진마다 위 1~6을 따로 거친다. 2480×3508 페이지에서 약 35~75ms.

## 테스트

[`test.html`](test.html)이 흰 배경 테스트 이미지를 Canvas로 만들어 실제 `app.js` 함수로 결과를 검증한다(경계 상자 정확도, 먼지 · 미색 노이즈, 임계값, 빈 이미지, 회전 방향, 여백, JPEG 압축, 기운 사진 · 옅은 경계선, 자동 기울기 각도 정확도 · 보정 후 크기 · 반듯한 사진/문서 미보정, 여러 장 분리(기운 4장 · 사진 1장/문서/빈 페이지 미분리), 문서 미적용, 4000×6000 성능, 띠 분할 병렬 분석 = 단일 분석, 워커 렌더 = 메인 렌더 픽셀 일치, 여러 장 동시 처리 속도, 워커/메인 스레드 일치). 아래 "내 이미지로 확인"에서 직접 고른 이미지의 결과 네 변에 남은 종이색 비율도 볼 수 있다.

## 로컬에서 실행

Web Worker · 다운로드가 `file://`에서는 막히는 브라우저가 있으니 간단한 서버로 연다.

```bash
# 저장소 루트에서
python -m http.server 8000
# → http://localhost:8000/  ·  테스트: http://localhost:8000/test.html
```

## GitHub Pages 배포

1. 이 저장소를 GitHub에 push한다.
2. **Settings → Pages → Build and deployment**에서 Source를 **Deploy from a branch**, Branch를 **main**, 폴더를 **/ (root)** 로 두고 Save.
3. 잠시 뒤 `https://<사용자명>.github.io/<저장소명>/` 에서 열린다(이 저장소는 https://yh-yeop.github.io/AutoCroper/).

`.nojekyll`이 Jekyll 처리를 끄므로 파일이 그대로 배포된다. 외부 CDN 없이 JSZip 3.10.1을 [`vendor/jszip.min.js`](vendor/jszip.min.js)로 포함한다(MIT, [라이선스](vendor/JSZIP-LICENSE.md)).

## 파일

```

test.html              알고리즘 테스트 페이지
vendor/jszip.min.js    ZIP 생성(로컬 포함)
desktop/               Windows 데스크톱 앱(Electron): main.js · preload.js · updater.js(자동 업데이트)
build/                 설치 파일 아이콘(icon.ico) · '연결 프로그램' 등록 스크립트(installer.nsh)
package.json           데스크톱 앱 · 설치 파일 설정(electron-builder)
.github/workflows/     v* 태그를 올리면 Windows에서 설치 파일을 빌드해 Releases에 올림
.nojekyll              Pages에서 Jekyll 끄기
LICENSE                MIT
```

웹 앱 파일을 고친 뒤에는 `sw.js`의 `VERSION`을 올려야 설치된 웹앱이 새 버전을 확실히 받는다.

```bash
npm ci
npm start            # 개발 실행
npm run dist:win     # Windows에서: dist/AutoCroper-Setup-<버전>.exe
```

릴리스: `package.json`의 `version`을 올려(`npm version patch --no-git-tag-version` 등) `main`에 push하면 끝. GitHub Actions(windows-latest)가 그 버전의 태그(`v1.0.1` 등)가 아직 없을 때만 설치 파일 · `latest.yml`을 빌드해 태그와 정식 릴리스를 만들고, 설치된 앱들이 자동으로 업데이트한다. 버전이 그대로면 빌드하지 않는다.

앱 파일을 고친 뒤에는 `sw.js`의 `VERSION`을 올려야 설치된 앱의 캐시가 확실히 바뀐다.

## 한계

- 여러 장 분리: 사진 사이 틈이 4px 정도로 좁아도, 크기가 같은 사진을 줄 맞춰 놓아도 나눈다. 나눈 영역 밖에 사진만 한 덩어리가 남으면 그것도 한 장으로 더해 사진이 사라지지 않게 한다. 사진 속 흰 선이 정확히 밝기 경계(하늘/바다)에 놓이면 잘못 나뉠 수 있다 — '한 장으로 되돌리기'. 경계가 곧고 넓은 완전히 흰 띠(날아간 하늘 · 흰 벽)가 사진 하나를 가로지르면 두 장으로 나뉠 수 있다 — 카드의 **분리 취소**로 되돌린다(잘못 합쳐지는 쪽보다 되돌리기 쉬워 이렇게 정함). 서로 닿아 있거나 틈이 아주 좁은 사진은 한 장으로 남는다. 페이지 넓이의 0.3% 미만인 아주 작은 사진은 영역으로 잡히지 않는다.

- iOS Safari 등은 캔버스 최대 면적이 작아(약 1,670만 픽셀) 아주 큰 결과는 만들지 못할 수 있다. 그때는 카드에 안내가 뜬다.
- HEIC 등 브라우저가 열지 못하는 형식은 지원하지 않는다.
- 자동 기울기 보정은 ±45°까지(15°보다 크면 볼록 껍질 · 최소 사각형으로 각도를 잼), 테두리가 곧은 사진에만 적용된다. 보정하면 한 번 보간되므로 아주 미세하게 부드러워진다. 그보다 큰 회전은 90° 회전 버튼으로.
